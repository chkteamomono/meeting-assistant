# 기획안 — 회의 보조 비서

`인사관리 보조 에이전트`(면접 보조 비서)와 같은 구조(로컬 웹앱, 마이크 → faster-whisper → Claude CLI)를 참고해서 만든 회의용 버전입니다.

## 무엇을 하는가

1. **오늘 회의 안건을 먼저 적어둔다** — 면접 보조 비서의 "면접 질문" 탭처럼, 화면을 열면 오늘 다룰 안건 목록이 맨 위에 먼저 보입니다. 회의 시작 전이든 진행 중이든 **언제든 추가·수정·삭제**할 수 있습니다 (제목을 클릭하면 바로 고칠 수 있음).
2. **회의 중 실시간 받아쓰기** — 마이크로 들리는 내용을 텍스트로 계속 저장
3. **각 안건의 진행 상황이 실시간으로 채워진다** — 25~30초 안팎마다, 지금까지 나온 이야기를 해당 안건과 연결지어 논의 요약·결정 사항·액션 아이템을 자동으로 채웁니다. 목록에 없던 새로운 주제가 뚜렷하게 나오면 새 카드가 자동으로 추가됩니다 (이때도 제목은 사용자가 나중에 고칠 수 있음).
4. **회의 종료 시 회의록 자동 생성** — 받아쓰기 전문 + 마지막 안건 상태를 바탕으로 공유용 회의록(.md)을 만들어 저장

면접 보조 비서와 다른 점: 지원자 선택·이력서 대조·차별 질문 경고 같은 면접 전용 기능은 없습니다. 핵심은 "안건 제목은 항상 사용자 소유, 진행 상황(요약·결정·액션 아이템)만 AI가 실시간으로 채운다"는 점 — AI가 회의 진행이나 결론을 대신 내려주지 않고, 오간 내용을 사용자가 정한 안건 틀 안에 구조화해서 보여주는 역할만 합니다.

## 화면 구성 (위에서부터)

- 회의 기업/상대 + 회의 주제 입력 + 시작/종료 버튼 + 경과 시간 + 통계 카드 3개(안건 수 · 결정됨 · 액션 아이템)
- **📌 오늘 회의 안건 (핵심, 항상 노출)** — 안건 카드 목록. 제목 클릭 → 바로 수정, ✕ → 삭제,
  맨 아래 입력창으로 새 안건 추가. 카드 안 요약·결정 사항도 클릭하면 직접 고칠 수 있음.
  AI가 채운 논의 요약 · 결정 사항 · 액션 아이템이 실시간으로 나타남.
- 🗒️ 메모 — 안건에 안 묶이는 내용을 자유롭게 적는 공간 (자동 저장)
- 🎤 실시간 받아쓰기 — 들리는 대로 흘러가는 자막 (보조 정보)
- 새 안건이 잡히거나 결정이 나면 화면 우측 아래에 토스트 알림

## 메모 (안건에 안 묶이는 자유 메모)

안건 패널 아래에 자유롭게 쓸 수 있는 메모 공간이 있습니다. 입력하면 잠시 후 자동 저장되고,
회의 종료 시 회의록을 만들 때 함께 반영됩니다 (받아쓰기보다 우선 신뢰됨 — 사람이 직접 쓴
내용이므로). 오탈자 걱정 없이 편하게 쓸 곳으로 쓰면 됩니다.

## 안건 요약·결정도 직접 고칠 수 있음

받아쓰기·AI 요약 모두 오탈자·오인식이 섞일 수 있습니다. 안건 카드의 요약/결정 사항 글을
누르면 바로 고칠 수 있고(제목과 마찬가지), 이 수정은 AI가 다시 덮어쓰지 않습니다 —
Claude는 사용자가 직접 고친 내용을 다음 갱신에서 존중하고 그 위에 새로운 내용만 더합니다.

## 인식률 — 원인은 "거리"가 아니라 "입력 경로"였음 (2026-09-10 확인)

처음엔 마이크와 화자 사이 거리 문제로 짐작했으나, 사용자가 **같은 시각·같은 자리**에서
Windows 기본 녹음기로 따로 녹음한 걸 이 앱의 실시간 받아쓰기와 비교해보니 거리는
원인이 아니었다. 실제 원인은:

- 이 앱이 쓰는 `sounddevice`(PortAudio)는 아무 지정 없이 열면 **Windows의 가장 오래된
  오디오 경로인 MME**로 잡힌다. 이 경로는 마이크 배열의 드라이버 단 처리(인텔 Smart
  Sound Technology의 빔포밍·잡음 억제·자동 게인)를 거치지 않은 날것 신호를 준다.
- Windows 기본 녹음기 같은 최신 앱은 **WASAPI**를 쓰는데, 이 경로에서는 그 처리가
  이미 적용된 신호를 받는다. 그래서 같은 물리적 마이크·같은 순간인데도 녹음기 쪽
  결과가 훨씬 또렷했던 것.
- 검증 방법: 사용자가 준 녹음 파일을 이 앱과 똑같이 10초씩 끊어 각각 인식시켜본 결과,
  10초로 끊는 것 자체는 품질을 거의 떨어뜨리지 않았다 (끊지 않고 통으로 인식한 것과
  결과가 거의 동일). 즉 "10초마다 자른다"는 구조는 범인이 아니었고, 입력 경로(MME
  vs WASAPI) 쪽이 실제 원인이라는 게 소거법으로 확인됨.

**조치**: `서버.py`가 실행될 때마다 WASAPI 기본 입력 장치를 직접 찾아서 그 장치로
녹음하도록 바꿨다 (`find_capture_device()`). 장치의 실제 표본화율(대개 48000Hz)로
받은 뒤 모델이 쓰는 16000Hz로 소프트웨어에서 다시 맞춘다(`resample_to_model_rate()`,
scipy 필요 — `requirements.txt`에 추가됨). WASAPI 장치를 못 찾으면 예전처럼 시스템
기본 장치로 조용히 되돌아간다.

이 조치는 콘솔에 `[Audio] WASAPI 입력 장치 사용: ...` 로그로 확인할 수 있다(이 줄이
안 뜨고 "시스템 기본 장치로 진행합니다"가 뜨면 WASAPI를 못 찾은 것 — 그래도 동작은
하지만 이전과 같은 품질일 수 있음). 게인 증폭·환각 억제 조치도 함께 남겨뒀지만,
이번 조사 결과 핵심 원인은 입력 경로 쪽이었다.

## 저장 위치

`03. 회의 기록/{날짜}_{회의 기업}_{회의 주제}/` 폴더에 아래가 저장됩니다 (기업을 안 적으면
`{날짜}_{주제}`). 같은 날 같은 기업·주제로 다시 시작하면 시각을 덧붙여 구분합니다.
- `회의녹취록_....md` — 받아쓰기 전문
- `메모_....md` — 회의 중 직접 남긴 메모 (메모를 하나도 안 썼으면 생성되지 않음)
- `안건판_....json` — 회의 종료 시점의 안건 목록 스냅샷 (제목·상태·요약·결정·액션 아이템)
- `회의록_....md` — Claude가 정리한 공유용 회의록 (종료 후 1~2분 뒤 생성)

## 참고자료

- `참고자료/회의록_형식.txt` — 회의록 작성 규칙(마크다운 템플릿). 비워두면 내장 기본 규칙 사용. 팀 고유 양식이 있으면 이 파일을 고쳐서 반영.
- `참고자료/받아쓰기_용어.txt` — 회의에서 자주 나오는 고유명사(사업명·기관명 등)를 적어두면 받아쓰기 정확도가 올라감. (형식은 면접 보조 비서와 동일)
